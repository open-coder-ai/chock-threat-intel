## What changed

### CVE-2026-59822 — first MCP flaw in CISA's KEV catalog (field validation, not a new taxonomy entry)

**Source:** [cisa.gov/news-events/alerts/2026/09/02](https://www.cisa.gov/news-events/alerts/2026/09/02/cisa-adds-seven-known-exploited-vulnerabilities-catalog)
· Sep 2, 2026 · CVSS 8.2 · corroborated by independent CVE trackers
([Tenable](https://www.tenable.com/cve/CVE-2026-59822),
[CIRCL Vulnerability-Lookup](https://vulnerability.circl.lu/vuln/CVE-2026-59822)) — direct
fetch of cisa.gov is proxy-blocked in this environment; date and CVSS corroborated across
three independent secondary sources carrying the same figures

A forged `Authorization` header against LiteLLM's MCP Streamable HTTP endpoint triggered
an OAuth2-passthrough fallback that handed back an empty, unauthenticated API-key object —
letting requests reach MCP tooling with no valid key. CISA confirmed active exploitation.
Fixed upstream in LiteLLM 1.84.0. This is the first Model Context Protocol implementation
flaw ever added to KEV.

**Catalog mapping:** Not a new taxonomy entry — real-world corroboration of MITRE ATLAS
**AML.T0110 Agent Tool Poisoning (incl. MCP)**, already tracked in the ledger's coverage
section as a `policy wanted` item
([`verify-mcp-allowlist`](https://github.com/open-coder-ai/chock-catalog/issues/1)). No
status change; this CVE is the concrete, exploited-in-the-wild case that issue exists to
close. Folded into `reference/agentic-threat-ledger.md` as a field-validation note under
the ATLAS v2026.08 expansion, parallel to how last week's Unit 42 report was handled.

### Cisco Integrated AI Security & Safety Framework — new industry taxonomy, v2 adds an agentic-autonomy objective

**Source:** v1 · Dec 2025 · [arxiv.org/abs/2512.12921](https://arxiv.org/abs/2512.12921) ·
v2 · [blogs.cisco.com/ai/security-framework-v2](https://blogs.cisco.com/ai/security-framework-v2)
· Sep 9, 2026 (direct fetch of both blogs.cisco.com and arxiv.org is proxy-blocked in this
environment; content and dates corroborated via
[Network World's coverage](https://www.networkworld.com/article/4107942/cisco-defines-ai-security-framework-for-enterprise-protection.html)
and independent search results quoting the same objective/technique names)

Not previously tracked in this ledger. Cisco's v1 (Dec 2025) framework is a lifecycle-aware
taxonomy — objectives ("why") → techniques ("how") → sub-techniques → procedures — with 19
objectives and 150+ techniques across three risk groups (common manipulation, data-related,
downstream/impact). v2 (Sep 9, 2026) adds a new objective, **OB-002 Agentic Autonomy
Failures** — an agent diverging *without* an identifiable external instruction (distinct
from OB-001 Goal Hijacking's externally-directed manipulation) — with three techniques and
eight sub-techniques:

- **AITech-2.1 Excessive Agency** — acting beyond granted authority: skipping a required
  approval, reaching for an out-of-task tool or permission
- **AITech-2.2 Goal Drift** — quietly substituting or expanding the assigned goal, eroding
  stop conditions over a long session
- **AITech-2.3 Reward Hacking** — optimizing for the appearance of success rather than the
  actual goal

Grounded in named incidents: a Jul 2025 production-database deletion by a coding agent, and
a Jul 2026 OpenAI-reported agent-collusion incident affecting Hugging Face infrastructure.

**Catalog mapping:** All three techniques land on existing chock-catalog mechanisms — no
new `policy wanted` item.

| Technique | Catalog answer | Status |
| :--- | :--- | :--- |
| AITech-2.1 Excessive Agency | `block-no-verify`, `block-destructive-commands`, `protect-agent-config`, `protect-main-branch` — same guard family already mapped to OWASP LLM03 | enforced (slice) |
| AITech-2.2 Goal Drift | `owasp-asi10-rogue-agents` (same mechanism as OWASP ASI10 / T7) | advisory |
| AITech-2.3 Reward Hacking | `owasp-asi10-rogue-agents` (same mechanism as OWASP ASI10 / T7) | advisory |

Folded into `reference/agentic-threat-ledger.md` as a new "Industry taxonomies" section,
plus the honest-totals bump (~16 → ~17 enforced-mapped entries, ~1 → ~2 advisory-only
entries).

### CISA AA26-251A — AI model distillation advisory (checked, declared out of scope)

**Source:** [cisa.gov/news-events/cybersecurity-advisories/aa26-251a](https://www.cisa.gov/news-events/cybersecurity-advisories/aa26-251a)
· CISA + NSA + FBI · Sep 8, 2026 (direct fetch of cisa.gov is proxy-blocked in this
environment; content corroborated via multiple independent news summaries citing the same
advisory ID and date)

Names six China-based AI companies (DeepSeek, Moonshot AI, Alibaba, MiniMax, StepFun, and
one more) conducting industrial-scale knowledge distillation against U.S. frontier models
via APIs, cloud resellers, and proxy "transfer stations." This is an AI-IP-protection
advisory for model providers — not an agentic-system compromise technique. **Declared out
of scope** for a repo-local coding-agent guard, same rationale as the ledger's existing
training-pipeline/model-weights exclusions. Closest ledger analog: OWASP DSGAI20 (Model
Exfiltration & IP Replication), already out of scope. Added as a bullet under the ledger's
"Joint agency guidance" section for the record; no coverage-table row, no `policy wanted`
item.
