## What changed

### MITRE ATLAS v2026.10's three open items, resolved: AML.T0138, T0142, T0143

**Source:** [ATLAS-2026.10.yaml](https://github.com/mitre-atlas/atlas-data/blob/main/dist/v6/ATLAS-2026.10.yaml),
fetched directly (github.com/raw.githubusercontent.com, no block). Last week's digest left three
v2026.10 techniques unscored because atlas.mitre.org's technique pages were DNS-blocked; the same
content is in the machine-readable release data already cited for this snapshot, which this
sweep used instead.

**AML.T0138 Indicator Removal** — deleting, altering, or falsifying logs, command histories,
files, metadata, repository history, or published content to hide activity, explicitly including
an autonomous agent tampering with its own transcripts or the harness components that record its
tool calls. Not a match for the existing T0101 Data Destruction row (which covers destroying
*target* data via a tool call, not the agent's own audit trail) — adjacent instead to this
ledger's own open roadmap gap, the tamper-evident gate log
([chock#33](https://github.com/open-coder-ai/chock/issues/33), OWASP T8), which nothing in the
catalog currently builds. **New coverage row: `policy wanted`.**

**AML.T0142 Event Triggered Execution** — persistence via event handlers or startup hooks (e.g.
interpreter startup hooks) that later activity — including **agent tool execution** — runs on its
own; triggered code can also emit fabricated approvals/instructions for the AI system to consume
later. Adjacent to `protect-agent-config`‡'s guarded config paths, but that guard covers
designated config files only, not arbitrary interpreter/runtime startup-hook mechanisms outside
them — the same "adjacent, not covered" pattern as the existing AML.T0018.003 row. **New coverage
row: `policy wanted`.**

**AML.T0143 LLM Prompt Propagation** — malicious instructions already present in an AI-enabled
environment transferred onward (email, shared documents, **source-code repositories**, agent
memory, retrieval systems, shared workspaces, agent-to-agent communication) so they affect later
AI activity without a fresh delivery to each target. This is the surface the ledger's prose
already names when citing AML.T0061 LLM Prompt Self-Replication as untracked — closest existing
coverage is OWASP ASI06 Memory & Context Poisoning / `memory-discipline`, already `advisory` for
exactly this class. **No new row** — maps onto existing coverage, same treatment as Cisco's
OB-002 techniques mapping onto existing ASI10 coverage without a new entry.

### Trojanized Claude Code VS Code extension, distributed via Cursor's own marketplace

**Source:** [Cursor's own security notice](https://cursor.com/blog/claude-code-extension-security-notice),
Oct 29–30, 2026. Corroborated via [The Hacker
News](https://thehackernews.com/2026/10/official-claude-code-vs-code-extension.html),
[Help Net Security](https://www.helpnetsecurity.com/2026/10/30/claude-code-extension-ssh-backdoor/),
[GovInfoSecurity](https://www.govinfosecurity.com/cursor-confirms-anthropic-claude-code-extension-compromised-a-33263),
[InfoWorld](https://www.infoworld.com/article/4243214/cursor-removes-malicious-claude-code-extension-after-ssh-backdoor-attempt-2.html),
and [Socket's registry analysis](https://socket.dev/blog/claude-code-extension-compromise)
(direct fetch of cursor.com and all five secondary sites is proxy-blocked in this environment;
used as corroboration only).

Versions 2.1.312 and 2.1.313 of the official Claude Code VS Code extension were tampered with and
distributed through **Cursor's own** VS Code extension marketplace — not Microsoft's Marketplace,
not Open VSX, not npm; all three are confirmed unaffected (Socket's analysis corrected an initial,
wrong report that Open VSX was hit too). The window was roughly 11 hours on Oct 29, 2026, reaching
up to 5,000 users by Cursor's own count. The malicious build ran a loader that collected host
information, added an attacker-controlled SSH key (labeled `svc-telemetry`) to
`~/.ssh/authorized_keys`, enabled the local SSH service, and opened a reverse connection — a
publish-time tamper under a legitimate-looking publisher identity, not a bug in Claude Code's own
code. Cursor's own analysis caveats that enabling SSH this way needed admin/root rights the
extension lacked on most Mac and Windows hosts, so the attacker likely could not actually log in
through the tunnel on most affected machines. Anthropic engineer Felix Rieseberg says Anthropic's
own systems were not breached; how the tampered build reached Cursor's marketplace under an
Anthropic-owned listing is unresolved as of this writing. Fixed in 2.1.314 (published Oct 30,
2026); anyone who installed 2.1.313 should check `~/.ssh/authorized_keys` for the `svc-telemetry`
key regardless of whether they've since updated.

**Catalog mapping.** Real-world corroboration of the same **AML.T0115 Publish Poisoned AI
Artifacts** / **AML.T0109 Supply-Chain Rug Pull** family as Plugin4Shell and GitSpawn — but a
different mechanism: Plugin4Shell broke a *pin-resolution* check, this broke an *IDE's own
marketplace* distribution surface. No chock-catalog policy reaches an editor's own extension
manager (`block-unpinned-agent-components`/`chock.lock` governs installs a governed repo makes
itself). Folded into the ledger as a **new scope boundary**, not a status change — `enforced
(slice)*` on the T0109/T0115 rows is unaffected because that status was never claimed to cover
this surface.

### CVE-2026-103572 — Visual Studio/SSMS Copilot RCE (backfill, disclosed Oct 13, 2026)

**Source:** Researcher Johann Rehberger; disclosed Oct 13, 2026, fixed the same day in Microsoft's
October Patch Tuesday. Corroborated via multiple secondary mirrors (direct fetch of
embracethered.com, msrc.microsoft.com, and the mirror sites is proxy-blocked in this environment)
agreeing on researcher, mechanism, CVSS 8.8, and patch builds. **Missed by the Oct 16 and Oct 23
sweeps — backfilled now**, same pattern as GitSpawn and the MCP TypeScript SDK batch.

`Microsoft.VisualStudio.Copilot.Core.dll` (shared by Visual Studio 2022/2026 and SQL Server
Management Studio) checks a Copilot-proposed file path as a string, but the underlying Win32 file
write silently strips a trailing dot; a path ending in `.` passes the string check and then
resolves to the real, protected config file once written — letting Copilot (including via
indirect prompt injection from processed content) overwrite protected IDE/MCP configuration and
reach arbitrary command execution. Fixed in builds 17.14.42 and 18.10.4.

**Catalog mapping.** Real-world corroboration of **AML.T0081 Modify Agent Configuration** — the
exact class `protect-agent-config`‡'s approval-marker guard exists for — in a vendor other than
chock's own tracked agents. This ledger can't confirm whether `protect-agent-config`'s own path
matching normalizes a trailing dot (or similar alternate path forms) the same way Windows does.
**New open verification flag (§)** added to the AML.T0081 coverage row. No status change.

### Check Point Research: "Haiou" — a new named class, "prompt adware"

**Source:** Check Point Research, ["Free the Model, Sell the Gateway: Prompt Adware hidden in
Jailbreak Bundles"](https://research.checkpoint.com/2026/free-the-model-sell-the-gateway-prompt-adware-hidden-in-jailbreak-bundles/),
with a companion post at
[blog.checkpoint.com](https://blog.checkpoint.com/security/prompt-adware-how-hidden-ai-instructions-could-create-a-new-enterprise-security-risk)
(secondary coverage via [SC World](https://www.scworld.com/brief/researchers-identify-prompt-adware-targeting-openai-codex);
direct fetch of both checkpoint.com domains is proxy-blocked in this environment), published Nov 3,
2026.

A public jailbreak package (bundle version 4.5.0) for OpenAI Codex (a less-maintained Claude Code
variant also exists) rewrites the agent's own global configuration and Skills files so specific
greeting triggers (e.g. "hi", "ctf") produce scripted promotional replies pointing to an
OpenAI-compatible LLM gateway the distributor runs — persistent natural-language edits to trusted
agent instructions for commercial ends, no executable payload required. Check Point notes Claude
Code / Sonnet 5 flagged the bundle's instructions and refused to apply them when tested. Check
Point's name for the class, "prompt adware," is new; found alongside offensive tooling (Cobalt
Strike) on a cybercrime group's public server, with no evidence tying the author to that group.

**Catalog mapping.** Not a framework release, a named attack pattern — but mechanically it is
**AML.T0081 Modify Agent Configuration** again, feeding **OWASP ASI10 Rogue Agents** / **T7
Misaligned & Deceptive Behaviors**. Unlike the Visual Studio case above, nothing here suggests
`protect-agent-config`‡ is defeated by this mechanism — a **positive** field validation. No status
change.

### Microsoft Threat Intelligence: ARTEX used at scale for secrets discovery (Nov 5, 2026)

**Source:** [Microsoft
Security blog](https://www.microsoft.com/en-us/security/blog/2026/11/05/threat-actors-use-agentic-ai-tooling-to-find-and-abuse-exposed-secrets/),
fetched directly (no proxy block on microsoft.com), Nov 5, 2026.

Follow-on to the CrowdStrike/ARTEX South Korean-banking campaign this ledger already tracks: an
unattributed actor used the same ARTEX agentic framework (Nmap, curl/wget, headless Chromium via
Playwright, and similar tools bundled by default) at broader scale — large-volume GitHub
code-search queries for exposed secrets, automated Entra ID service-principal sign-ins with the
leaked credentials, enumeration/exfiltration via Key Vault, Storage, SharePoint and Graph, and
adaptive HTTP-verb/API-version retries on failure. One case went from a GitHub secret search to
exfiltrated Key Vault data in five minutes.

**Catalog mapping.** Further corroboration of **AML.T0098 Agent Tool Credential Harvesting** and
**AML.T0053 AI Agent Tool Invocation** (both already `advisory`/`enforced (slice)` via
`scan-secrets`), and of the autonomous-operation techniques already declared out of scope. No
status change — this is attacker-side use of already-exposed secrets, not a gap in a chock-governed
repo's own secret scanning.

## Backfilled into the ledger: MLCommons Agent Privacy Risk Taxonomy v0.1

**Source:** [mlcommons.org/2026/10/agent-privacy-risk-taxonomy-v0-1](https://mlcommons.org/2026/10/agent-privacy-risk-taxonomy-v0-1/),
announced Oct 1, 2026 (direct fetch of mlcommons.org is proxy-blocked in this environment). A
first-draft (v0.1, unranked) taxonomy from MLCommons (the MLPerf benchmarking consortium) covering
five areas of agent privacy risk: data ingestion/processing, data aggregation/use/sharing,
inconsistent cross-agent privacy practices, accountability/governance gaps, and user consent and
expectations — roughly 24–25 specific risks across those areas (secondary sources disagree on the
exact count, and the exact area labels/order could not be confirmed against the primary page this
sweep either, so the full list isn't enumerated here, treated as approximate pending a direct
read). Added as a new tracked body under "Industry taxonomies," **declared out of scope**: this
is agent *input*/data-lifecycle governance, not tool-call runtime behavior a repo-local guard
observes — same rationale as OWASP LLM09/the Data Security document.
