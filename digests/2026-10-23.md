## What changed

### MCP TypeScript SDK — seven advisories (four backfilled, three new this window)

**Source:** GitHub Security Advisories, `modelcontextprotocol/typescript-sdk`, published by
maintainer `maxisbey` — all seven fetched directly, no proxy block on github.com:

**New to this sweep's Oct 9–23 window (disclosed Oct 15, 2026):**

- [GHSA-jm63-cq47-j5jp](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-jm63-cq47-j5jp)
  — "Shared transport or server instances delivered one HTTP client's messages to another" (High,
  CVSS 7.7, CVE-2026-111770, CWE-362). A shared transport/server instance matched responses to
  clients by JSON-RPC `id` alone; low IDs collided, so one client could receive another client's
  responses and notifications. Patched in `@modelcontextprotocol/server` 2.3.0 — which then
  *rejects* shared instances, requiring a code change (one server per request/session/factory).
- [GHSA-46jr-4wx8-v453](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-46jr-4wx8-v453)
  — "One HTTP request within the default size limit could exhaust server memory during
  validation" (High, CVSS 7.5, CVE-2026-111768, CWE-770). A single request under the default 4
  MiB body limit could exhaust memory validating array/object depth. Patched in
  `@modelcontextprotocol/sdk` 1.32.0 / `server` 2.3.0, but the new `maxToolInputElements` guard is
  off by default — upgrading alone does not close it.
- [GHSA-f897-62hf-6gxq](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-f897-62hf-6gxq)
  — "HTTP server transports and handlers did not limit request body size or JSON-RPC batch
  length" (High, CVSS 7.5, no CVE assigned, CWE-770). No cap on POST body size or batch message
  count. Patched across `sdk` 1.30.1, `server` 2.1.0, `node` 2.1.0, `hono` 2.0.1 (caps bodies at 4
  MiB, batches at 100 messages).

**Backfilled (disclosed Sep 30 – Oct 5, 2026, before this ledger's own 14-day cutoff but missed
by the Oct 9 digest, which scoped its MCP-SDK check to `python-sdk` only):**

- [GHSA-6qxp-vccf-f47h](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6qxp-vccf-f47h)
  (Sep 30, High, CVSS 7.5, CVE-2026-104850, CWE-345/522) — OAuth client credentials not bound to
  their issuing server; a malicious MCP server could redirect stored refresh tokens/client
  secrets to itself. The `python-sdk` analog of this bug (GHSA-qx49) was already in the Oct 9
  digest; this is the same class in the TypeScript implementation.
- [GHSA-22jm-h49p-29qw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-22jm-h49p-29qw)
  (Oct 2, High, CVSS 8.6, CVE-2026-111767, CWE-639/862) — **no `python-sdk` analog.** A shared
  `InMemoryTaskStore` for the experimental "tasks" feature did not check which session created a
  task; any client sharing the store could list, read, or cancel another client's tasks.
- [GHSA-6prh-2h8m-c8cw](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-6prh-2h8m-c8cw)
  (Oct 2, Moderate, CVSS 6.5, CVE-2026-111769, CWE-200) — cross-origin redirects re-sent custom
  headers, the `mcp-session-id` header, and (on 307/308) the request body to the new origin.
  Analog of `python-sdk`'s GHSA-5h93 from the Oct 9 digest.
- [GHSA-rvq5-wwqv-78pq](https://github.com/modelcontextprotocol/typescript-sdk/security/advisories/GHSA-rvq5-wwqv-78pq)
  (Oct 5, Moderate, CVSS 6.8, CVE-2026-111771, CWE-863) — server bearer-token audience confusion;
  analog of `python-sdk`'s GHSA-w4fh from the Oct 9 digest.

All seven are patched (version ranges vary by advisory — see the ledger's MITRE ATLAS
field-validation callout for the full table), but three of the fixes (`expectedIssuer`,
`expectedResource`, `maxToolInputElements`) are opt-in settings rather than defaults, so a bare
version bump does not close every one of them.

**Catalog mapping — field validation, no status change.** Five of the seven are the same bug
classes the Oct 9 digest already mapped for the Python SDK batch: **AML.T0098 Agent Tool
Credential Harvesting** (OAuth redirection), a header/body leak via cross-origin redirect
(CWE-200), **OWASP ASI03 Identity & Privilege Abuse** (audience confusion), and **OWASP T4
Resource Overload / LLM06 Unbounded Consumption / AML.T0034.002** (the two Oct 15
resource-exhaustion bugs). The two bugs with no Python-SDK analog — the cross-session task leak
(GHSA-22jm) and the cross-client response-delivery leak (GHSA-jm63) — are new instances of the
same bucket: **OWASP ASI03 Identity & Privilege Abuse / LLM02 Sensitive Information Disclosure**,
specifically a multi-tenant-deployment risk (one MCP server process serving several clients)
rather than the single-client-vs-malicious-server shape of the other five. None of this changes
any row's status: this ledger's AML.T0110 row already states the limit of
`verify-mcp-allowlist`'s `enforced (slice)` coverage — "membership is checked, not what an
allowed server's tools say or return" — and these seven are exactly that, field validation of an
already-declared gap, not a new open question. `verify-mcp-allowlist` is unaffected: chock does
not vendor or run the MCP TypeScript SDK, same declared-scope posture as the Python SDK batch,
Plugin4Shell, and GitSpawn being bugs in other projects' / vendors' code, not chock's own
mechanism.
