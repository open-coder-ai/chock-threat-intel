# Digest — 4 September 2026

Delta against [2026-08-28.md](2026-08-28.md), one week prior. An active week after three
quiet ones: MITRE ATLAS shipped its largest single-release technique expansion since the
agentic buildout began, OWASP donated a new runtime-control standard, and Unit 42
published a field report that independently corroborates ATLAS's new autonomous-operation
techniques.

## What changed

### MITRE ATLAS v2026.08 — 19 new technique/sub-technique IDs, one tactic renamed

**Source:** [github.com/mitre-atlas/atlas-data releases/v2026.08](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.08)
· Sep 1, 2026 · confirmed directly against the machine-readable
[ATLAS-2026.08.yaml](https://github.com/mitre-atlas/atlas-data/blob/main/dist/v6/ATLAS-2026.08.yaml)
release data (cloned and diffed against the prior v2026.07 snapshot, not taken from a summary)

Technique/sub-technique count rises from 178 to 197 (114 techniques + 83 sub-techniques);
mitigations from 37 to 39; case studies from 68 to 72. The tactic **AML.TA0001** is renamed
from "AI Attack Staging" to **"AI Attack Adaptation."** Nineteen new IDs:

- **Autonomous operation:** AML.T0116 Autonomous Reconnaissance · T0117 Autonomous
  Attack-Path Adaptation · T0124 Autonomous Attack Orchestration
- **Inter-agent communication:** AML.T0118 Autonomous AI Agent Communication, with
  sub-techniques T0118.000 (Communication via Shared Artifacts) and T0118.001 (Direct
  Agent Communication)
- **Agent-tool tradecraft:** AML.T0016.004 / T0017.002 AI Agent Tools (obtaining vs.
  developing malicious agent tools/tool servers) · T0016.003 Exploits · T0017.001
  Autonomous Exploit Development
- **General ATT&CK-lineage techniques newly modeled against AI infrastructure:**
  T0119 Exploit Automated Artifact Processing Pipeline · T0120 AI Artifact Repository
  (as an async C2 channel) · T0121 AI Agent Environment Reconstruction · T0122
  Exploitation of Remote Services · T0123 Obfuscated Files or Information · T0125
  Create Account · T0126 Automated Collection · T0127 Data Staged · T0128 Compromise
  Infrastructure

**Catalog mapping:** Two entries are in scope for a repo-local coding-agent guard and are
already covered by existing catalog policies — no new `policy wanted` item this week:

| Entries | Catalog answer | Status |
| :--- | :--- | :--- |
| AML.T0118, .000–.001 (agent-to-agent comms) | `owasp-asi07-insecure-inter-agent-communication` | advisory |
| AML.T0016.004, T0017.002 (malicious agent tools) | `block-unpinned-agent-components` (hash-pinned `chock.lock` installs) — same mechanism as T0109/T0115 | enforced (slice) |

The remaining 14 new IDs (T0116, T0117, T0119, T0120, T0121, T0122, T0123, T0124, T0125,
T0126, T0127, T0128, T0016.003, T0017.001) describe an adversary's own autonomous
reconnaissance, exploitation, C2, and infrastructure tradecraft against systems outside the
repository a coding-agent guard governs — declared **out of scope**, same rationale already
applied to AML.T0105 (Escape to Host).

Folded into `reference/agentic-threat-ledger.md`: the ATLAS Source line, the AML.TA0001
rename, a new "v2026.08 expansion" bullet block, two new coverage-table rows, an
out-of-scope note for the rest, and the honest-totals count (~14 → ~16 framework entries
covered).

### OWASP Agent Control Standard (ACS) — new runtime-control standard donated to the GenAI Security Project

**Source:** [genai.owasp.org, Sep 1, 2026](https://genai.owasp.org/2026/09/01/owasp-genai-security-project-unveils-2026-top-10-for-llm-applications-new-agent-control-standard-and-sponsors-as-community-tops-30000-members/)
· canonical project: [github.com/GenAI-Security-Project/agent-control-standard](https://github.com/GenAI-Security-Project/agent-control-standard)
· v0.1 Public Preview

An existing open-source project — declarative hooks, policy enforcement, and observability
(OpenTelemetry/OCSF telemetry, plus an Agent Bill of Materials in CycloneDX/SWID/SPDX)
across agent frameworks — was donated to and announced by the OWASP GenAI Security Project
alongside this year's LLM Top 10 press cycle. It is a **control standard, not a threat
taxonomy**: nothing in it names a new threat entry to score, and at v0.1 Public Preview
(roadmap to v3) it's too early-stage to crosswalk against catalog policies with a straight
face. Added to the ledger's OWASP companion-documents list for tracking; no coverage-table
row, no new `policy wanted` item — a scoring pass belongs in a later digest once the
standard stabilizes past preview.

### Unit 42 — AI-assisted attack investigation (field validation, not a new taxonomy entry)

**Source:** [unit42.paloaltonetworks.com](https://unit42.paloaltonetworks.com/ai-assisted-cyber-attack-inside-a-unit-42-investigation/)
· published ~[Sep 3, 2026](https://www.resultsense.com/news/2026-09-03-ai-agent-ransomware-unit42)
(direct fetch of unit42.paloaltonetworks.com is proxy-blocked; date corroborated via a
secondary write-up carrying the same publication date in its own URL/slug)

A human attacker directed frontier-model agents through an automated attack loop,
compressing what the report describes as weeks of manual intrusion tradecraft (50+
ATT&CK/ATLAS-style techniques — internal mapping, source-repo access, root-credential
seizure) into under 10 hours. This is a real incident report, not a new numbered entry in
Unit 42's existing nine-scenario framework, and not itself a new taxonomy from a named
publisher — consistent with how prior digests have treated incident writeups. It is,
however, directly relevant as real-world corroboration of MITRE ATLAS's new
autonomous-operation techniques above (T0116, T0117, T0124), so it's folded into the
ledger's Unit 42 section as a citation-backed field-validation note rather than a scored
entry of its own. No catalog mapping change.
