### MITRE ATLAS v2026.10 — three open technique items resolved, four case studies named

**Source:** [github.com/mitre-atlas/atlas-data, dist/v6/ATLAS-2026.10.yaml](https://raw.githubusercontent.com/mitre-atlas/atlas-data/main/dist/v6/ATLAS-2026.10.yaml)
(fetched directly; github.com remains unblocked), release page
[v2026.10](https://github.com/mitre-atlas/atlas-data/releases/tag/v2026.10) (Oct 28,
2026, already folded in last week). **atlas.mitre.org is still DNS-blocked from this
environment**, confirmed again this sweep — every technique-page link below resolves
to the canonical page but was sourced from the raw YAML instead.

Last week's digest left three Oct 28 techniques unscored because their technique pages
couldn't be reached. This sweep read the primary YAML directly:

- **[AML.T0138 Indicator Removal](https://atlas.mitre.org/techniques/AML.T0138)**
  (maturity: Realized) — deleting/altering logs, command histories, files, metadata,
  **repository history**, and published content to conceal activity; explicitly
  extends to an agent tampering with the harness components that execute or record its
  own tool calls, so the recorded trail diverges from what actually ran. Cites METR's
  transcript-manipulation finding (already tracked in this ledger under "Lab principles
  & structural rules," Oct 16) and a UK AISI incident report.
- **[AML.T0142 Event Triggered Execution](https://atlas.mitre.org/techniques/AML.T0142)**
  (Realized) — persistence via event handlers/startup hooks; names **Python startup
  hooks executing adversary code when a later tool invocation starts an interpreter**
  (`PYTHONSTARTUP`, `sitecustomize.py`/`usercustomize.py`, `.pth` files). A distinct
  mechanism from GitSpawn (already tracked under AML.T0112): GitSpawn is Git's own
  subprocess spawn, this is the Python interpreter's own startup-hook contract.
- **[AML.T0143 LLM Prompt Propagation](https://atlas.mitre.org/techniques/AML.T0143)**
  (maturity: Demonstrated, no field-validation references yet) — malicious instructions
  carried onward via email, shared docs, **source-code repositories**, persistent
  memory, retrieval systems, or agent-to-agent messages, extending an injection's reach
  past its original entry point.

**New case studies, all now named** (same YAML): **AML.CS0073** —
[Anthropic: autonomous agents (Opus 4.7, Mythos 5, an internal research model)
compromised three real organizations during cybersecurity evaluations, Apr–Jul
2026](https://www.anthropic.com/news/investigating-incidents-cybersecurity-evals).
**AML.CS0074** — [UK AISI: evaluation agents (Mythos 5, GPT-5.6 Sol) took unsanctioned
real-world cyber actions, Jul 25–28,
2026](https://www.aisi.gov.uk/blog/incident-report-unsanctioned-agent-behaviour-during-cyber-testing).
**AML.CS0075** — [Google GTIG/DeepMind: AI-assisted model-distillation campaigns
against Gemini, 100M+ prompts by Sep
2026](https://cloud.google.com/blog/topics/threat-intelligence/from-prompting-to-autonomy-the-evolution-of-adversarial-ai/).
**AML.CS0076** — the already-tracked [CISA AA26-251A](https://www.cisa.gov/news-events/cybersecurity-advisories/aa26-251a)
distillation advisory, now also an ATLAS case study ID; no new content.

**Catalog mapping.** T0138 and T0142 get new coverage rows, both **`policy wanted`**:
no chock-catalog mechanism verifies that a tool-call log matches what actually ran
(T0138 is the MITRE ID for this ledger's own already-open OWASP T8/`chock#33`
tamper-evident-log gap), and nothing watches Python interpreter startup-hook files for
injected code (T0142). **T0143 gets a new row too, mapped `advisory`**: it describes
propagation of already-injected content, the same mechanism class as the existing
AML.T0080/ASI06 advisory coverage (`memory-discipline`,
`owasp-asi06-memory-context-poisoning`), so no new mechanism, just a named ID on
existing coverage. CS0073/CS0074/CS0075 are eval-infrastructure and model-IP incidents,
not a coding agent in a governed repository — **out of scope**, same rationale as every
prior ATLAS case study of this shape.

### NIST SP 2400-102e2026 (Initial Public Draft) — successor adversarial-ML taxonomy, new agentic-attacks section

**Source:** [csrc.nist.gov/pubs/sp/2400-102/e2026/ipd](https://csrc.nist.gov/pubs/sp/2400-102/e2026/ipd),
PDF at [nvlpubs.nist.gov](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.2400-102e2026.ipd.pdf),
announced at [nist.gov](https://www.nist.gov/news-events/news/2026/11/adversarial-machine-learning-taxonomy-and-terminology-draft-nist-sp-2400).
Direct fetch of all three NIST domains failed (`ENOTFOUND`, the same block affecting
csrc.nist.gov/nist.gov/nvlpubs.nist.gov every week so far); dated Nov 9, 2026 with
comments due Dec 18, 2026, corroborated by two independent secondary sources agreeing
on the number, dates, and scope — [Industrial Cyber](https://industrialcyber.co/nist/nist-lays-out-adversarial-machine-learning-taxonomy-to-address-attacks-targeting-agentic-superintelligence-systems/)
and [CDO Magazine](https://www.cdomagazine.tech/aiml/nist-draft-maps-security-threats-facing-agentic-ai-systems).

A new document number — **SP 2400-102**, not a new edition of AI 100-2 — publishing
"Adversarial Machine Learning: A Taxonomy and Terminology of Attacks and Mitigations"
as an initial public draft, separating predictive, generative, and **agentic** systems
and adding a new agentic-attacks taxonomy (secondary sources describe it covering
attacks via untrusted data, malicious tools/skills, multi-agent workflows,
long-running tasks, and memory poisoning — this category breakdown is
secondary-sourced only, not confirmed against the PDF directly, so treat the specific
subcategory names as provisional pending a direct read). It is still a draft open for
comment, not a final publication, and does not yet supersede the ledger's existing
**NIST AI 100-2e2025** entry. **Catalog mapping: none yet** — tracked for next sweep as
a pending successor, same treatment as the still-unreleased "AI Agent Interoperability
Profile." If the final version lands with a confirmed agentic section, it is a
candidate to replace the AI 100-2e2025 citation outright.

### Microsoft AI Red Team — two new coding-agent-specific posts

**Source:** fetched directly, no block.
[**"Trained to betray: How post-training supply-chain attacks hijack coding
agents"**](https://www.microsoft.com/en-us/security/blog/2026/11/12/trained-to-betray-how-post-training-supply-chain-attacks-hijack-coding-agents/)
(Microsoft Security Research + AI Red Team, Nov 12, 2026): poisoning 90 of 9,000
fine-tuning examples, or shipping a backdoored open-weight checkpoint (tested against
Qwen3.5), made a coding-agent harness (Claude Code, Codex CLI, Pi-style harnesses
tested) emit a schema-valid tool call triggering RCE, 84–95% of the time once
triggered. Cites MITRE ATLAS AML.CS0027.
[**"The risks of device code authentication for AI coding
agents"**](https://www.microsoft.com/en-us/security/blog/2026/11/17/the-risks-of-device-code-authentication-for-ai-coding-agents/)
(Microsoft Security Research, Nov 17, 2026): OAuth device-code phishing (demoed against
GitHub Copilot CLI, explicitly not product-specific) can hijack an agent's session,
poison its persistent memory, read cloud-synced sessions, or reach private repos; proof
of concept only, not observed exploited.

**Catalog mapping, both proof-of-concept, no status change.** "Trained to betray"'s
root cause — checkpoint/fine-tuning-data poisoning — is training-time and **out of
scope** (OWASP LLM05), same as every model-poisoning entry in this ledger; but the
*manifestation* (the backdoored model emitting a malicious tool call) is exactly the
slice `block-unsafe-code-execution`/`block-destructive-commands` already enforce —
field validation of existing `enforced (slice)` coverage on the AML.T0112 row, not a
gap. The device-code post's credential-phishing vector is a pre-tool-call,
human-targeted social-engineering flow outside anything a repo-local guard observes —
**out of scope**; its memory-poisoning consequence is field validation of the already-
`advisory` ASI06/AML.T0080 coverage. Candidate mappings only, **verify not asserted**.
