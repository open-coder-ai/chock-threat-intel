### NIST SP 2400-102e2026 (initial public draft) — first NIST taxonomy with a dedicated agentic attack index

**Source:** NIST's own draft announcement page,
[csrc.nist.gov/News/2026/adversarial-machine-learning-taxonomy-2026-draft](https://csrc.nist.gov/News/2026/adversarial-machine-learning-taxonomy-2026-draft),
dated Nov 9, 2026; PDF at
[nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.2400-102e2026.ipd.pdf](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.2400-102e2026.ipd.pdf)
(direct fetch of both csrc.nist.gov and nvlpubs.nist.gov is DNS-blocked in this environment; read
via WebSearch-indexed snippets of NIST's own pages, not a secondary aggregator).

"Adversarial Machine Learning: A Taxonomy and Terminology of Attacks and Mitigations," authored by
Vassilev, Oprea, Fordyce, Davies and Hamin, is the initial public draft of the successor to this
ledger's existing NIST AI 100-2e2025 entry. It adds a new, dedicated "Agentic SI [Super
Intelligence] Attacks Taxonomy" index — reportedly organized under the same five attacker-objective
groups as the parent document (availability, integrity, privacy, misuse, supply chain) — the first
NIST taxonomy edition to give agentic systems their own attack index rather than a single
"Security of Agents" subsection. Comment period open through Dec 18, 2026; nothing here is final.
The document uses "Super Intelligence (SI)" rather than "AI" throughout, per Executive Order 14434
(see the backfilled item below) — a terminology shift this ledger could not independently verify
against the PDF itself (network-blocked) beyond NIST's own page title and node text agreeing on it.

**Catalog mapping.** Still a formal governance taxonomy, not a runtime-detectable technique list —
same **out of scope** rationale this ledger already applies to its NIST AI 100-2e2025 parent and
to NIST AI 600-1. Tracked as a citation update to the existing NIST AI 100-2e2025 section (draft
successor, not yet superseding it); no coverage-table row, since none of NIST's governance
material gets one today. Flagged for next sweep: confirm the agentic-index item count and exact
attacker-objective labels once a primary fetch is possible, and watch for the final release.

### Microsoft: OAuth device-code phishing against AI coding agents (lab demonstration)

**Source:** [Microsoft Security
blog](https://www.microsoft.com/en-us/security/blog/2026/11/17/the-risks-of-device-code-authentication-for-ai-coding-agents/),
Uri Oren and Dor Edry, Nov 17, 2026 (fetched directly, no block on microsoft.com).

A lab proof-of-concept, not an observed-in-the-wild attack: classic OAuth device-code phishing —
an attacker starts a device-flow sign-in and lures a victim into entering the code on the real
provider page — aimed at an AI coding agent rather than a human's own session. The authors
demonstrate it against GitHub Copilot CLI because it supports the device flow, runs commands,
retains memory, and can sync sessions or accept remote steering; they're explicit that any public
device-flow client could be abused the same way. Once authorized, the attacker's session can (in
their four demonstrated outcomes) remotely steer an active Copilot CLI session, write misleading
entries into its persistent memory, read cloud-synced sessions, or reach private repositories the
victim's account can access — scoped entirely by whatever permissions and features that account
already had. No CVE; Microsoft frames the outcomes as features working as designed, not a bug, and
pairs the post with Defender detections correlating phishing clicks to GitHub OAuth token events.

**Catalog mapping.** Adjacent to **AML.T0098 Agent Tool Credential Harvesting** (`scan-secrets`,
`advisory`/`enforced (slice)` slice) and **OWASP ASI03 Identity & Privilege Abuse**
(`block-wildcard-iam`, `block-wildcard-agent-permissions`), but the compromise happens entirely
outside any tool call a repo-local guard observes — the phishing page is the real provider's own
site, the approval is the victim's own click, and the agent never makes a flagged tool invocation
during the authorization itself. Same boundary already declared for AML.T0105 Escape to Host and
the Cursor-marketplace extension tamper: a **new scope-boundary note**, not a status change, on
the AML.T0098/ASI03 rows. No new coverage row.

### Unit 42: ARTEX/CyberStrikeAI at internet scale, and a new named campaign — the Cairn framework (CL-STA-1238)

**Source:** Unit 42's own posts — ["ARTEX and AI-Powered Red Teaming Tools: What Defenders Need to
Know"](https://unit42.paloaltonetworks.com/artex-and-ai-powered-red-teaming-tools/), ~Nov 11, 2026,
and ["Cairn Framework: AI Autonomous
Attacks"](https://unit42.paloaltonetworks.com/cairn-framework-ai-autonomous-attacks/), ~Nov 12,
2026 (direct fetch of unit42.paloaltonetworks.com is DNS-blocked in this environment; corroborated
via [Dark Reading](https://darkreading.com/cyberattacks-data-breaches/china-nexus-actors-breach-10-organizations-ai-driven-attacks),
[CSOonline](https://www.csoonline.com/article/4247565/palo-alto-tracks-a-massive-chinese-ai-attack-that-sadly-lives-up-to-industry-fears.html),
[GovInfoSecurity](https://www.govinfosecurity.com/chinese-actor-automates-attacks-on-us-defense-chip-firms-a-33392),
and [Help Net Security](https://www.helpnetsecurity.com/?p=391032), all agreeing on dates, scale,
and the CL-STA-1238 tracking name).

Two distinct items. First, Unit 42 reports 609 internet-facing ARTEX hosts and 1,323 CyberStrikeAI
hosts observed as of October 2026 — ARTEX's original author has since closed its source. Second,
and new: **Cairn**, a separate open-source AI pentesting framework, used by a China-nexus actor
Unit 42 tracks as **CL-STA-1238** (moderate confidence) to run roughly 25 autonomous operations
against at least 19 organizations — mostly semiconductor, U.S. defense, and civil-society targets —
between August and September 2026, breaching 10 of them. The operator reportedly supplied only a
target and a one-line goal; Cairn (paired with Chinese models — DeepSeek and Zhipu GLM, per
secondary reporting) planned, executed, and recorded results on its own. Unit 42's own assessment:
autonomous AI raised the volume and reach of the campaign, not its sophistication — the operations
succeeded by exploiting already-known security gaps, not novel ones.

**Catalog mapping.** Both are further field validation of the same v2026.08 autonomous-operation
techniques (**AML.T0116, T0117, T0124**) and **AML.T0053 AI Agent Tool Invocation** already
field-validated by CrowdStrike's South Korean-banking report and declared **out of scope** — the
attacker's own tooling and infrastructure, not something a victim's (or anyone's) repo-local guard
reaches. No new coverage row, no status change; Cairn is tracked here as a newly-named tool/
campaign for future cross-reference.

### Cursor/Fireworks AI: root cause of the Oct 29–30 trojanized Claude Code extension (update)

**Source:** Cursor's own account, reported Nov 13, 2026, via
[BleepingComputer](https://www.bleepingcomputer.com/news/security/cursor-confirms-security-breach-led-to-malicious-claude-code-extension/)
and [Dark Reading](https://darkreading.com/application-security/cursor-malicious-claude-code-extension-third-party-breach)
(direct fetch of cursor.com is proxy-blocked in this environment, as already noted for this
incident in the Nov 6 ledger entry; both secondary sources agree on the chain and have not been
disputed by Fireworks).

**Update to the ledger's existing field-validation callout.** Cursor traces the already-tracked
Oct 29–30, 2026 tampered Claude Code extension to a stolen access key it had issued to Fireworks
AI, used to read a storage bucket shared between the two companies that held coding-agent traces —
some containing unredacted credentials. Fireworks' own October incident disclosures mention exposed
API keys and tokens but do not confirm this specific chain; neither company has dated when the key
was taken. Cursor says it has revoked the key, cut Fireworks' access to the shared bucket, and
moved its inference traffic off Fireworks. **No new mechanism and no status change** — this
confirms the "how" behind a compromise this ledger already scoped as outside any chock-catalog
policy's reach (an IDE's own extension marketplace and its vendor-to-vendor data sharing, not a
governed repository).

## Backfilled: Executive Order 14434 renames NIST's COSAiS project to COSIS

**Source:** [White House fact
sheet](https://www.whitehouse.gov/fact-sheets/2026/09/fact-sheet-president-donald-j-trump-inaugurates-the-era-of-super-intelligence/),
Executive Order 14434, "Inaugurating the Era of Super Intelligence," signed Sep 29, 2026;
NIST's own project page move to `csrc.nist.gov/Projects/cosis`, dated by NIST to Oct 20, 2026
(direct fetch of both whitehouse.gov and csrc.nist.gov is DNS-blocked in this environment;
corroborated via [Wiley Law's client alert](https://www.wiley.law/alert-Executive-Order-Rebrands-AI-as-Super-Intelligence-and-Signals-Potential-Federal-Legislative-Changes)
and a [Cloud Security Alliance research
note](https://labs.cloudsecurityalliance.org/research/csa-research-note-eo14434-super-intelligence-caissi-20261007/),
both agreeing on the EO number, date, and rename mechanics).

Predates this ledger's Nov 6 update and was missed by the prior sweep — backfilled now, same
pattern as GitSpawn and the MCP TypeScript SDK batch. EO 14434 directs federal agencies to replace
"artificial intelligence"/"AI" with "Super Intelligence"/"SI" in non-statutory materials; NIST's
**COSAiS** (Control Overlays for Securing AI Systems) project is now **COSIS** (Control Overlays
for Super Intelligence Systems), and CAISI is now CAISSI. NIST states previously issued
publications are unaltered, and the rename has no effect on the overlays' substance: still the
same five proposed overlays (including Using AI Agent Systems: Single Agent and Multi-Agent),
still in active development, no published draft found this sweep either. **Tracking/naming note
only** — this ledger's "NIST agentic pipeline (in progress)" section is updated to the current
project name and link; no coverage-table change, same out-of-scope governance rationale as before.
